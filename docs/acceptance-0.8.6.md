# 作家工作台 0.8.6 验收

## 本轮范围

另一台 Windows 电脑在点击「保存并打开安装器」后显示笼统错误。截图不足以区分保存失败、助手无法启动或缓存文件丢失；本轮针对可复现的更新缺陷修复，并分别报告这些错误。

Windows 参数矩阵实测发现，原有 detached 后台方式会使 PowerShell 直接退出且未执行脚本；改为隐藏引导进程，通过 .NET 创建独立的隐藏工作进程，确认真正的工作进程就绪后才退出。安装助手使用系统目录中的固定 PowerShell 路径，不依赖 PATH。进程等待、文件属性、SHA256 与安装器启动均使用系统自带 .NET API，避免依赖可选 PowerShell 模块。只有助手输出就绪确认后才进入最终保存和退出；未响应、缺失或系统阻止启动时保留工作台，不宣称已安装。关闭前再次保存；保存失败或超时取消等待中的助手，保留用户窗口和修改。

安装互斥覆盖整个流程，重复安装或操作系统关闭不会覆盖保存确认。保存请求共用在途结果，旧确认或超时不清空新的请求。Linux 托管更新同步交接重启锁，Mac 与 DEB 沿用原安装器交接。

缓存安装包丢失时恢复重新下载入口。短错误说明附安全代码，区分保存、助手、文件丢失及权限；不显示原始进程日志、用户路径或密钥。有效安装包仍可重试，失败不关闭工作台。

## 验收方式

所有测试使用受控 VM、隔离缓存或临时程序，不读取真实用户书稿。Windows 原生测试编译一个只在临时目录写标记的 C# 程序，使用符合安装包命名的文件名；只执行这个测试程序，不执行真实升级安装器。

原生检查覆盖取消后两个助手均停止、以后退出不误安装，以及 PowerShell 不在 PATH、中文 / 空格 / 单引号路径、就绪确认、父进程退出前不执行、父进程退出后执行，以及二次 SHA256 检查拒绝改动文件。原生安装包仍按四平台完整流程验收。结果将在实际构建和独立下载校验后记录。

## 旧版 Windows 升级
