# 作家工作台 0.2.0 验收记录

验证日期：2026-10-09。交付名称为「作家工作台 / Writer’s Desk」，当前实际构建和运行的平台为 Linux x64。

## 用整部小说检验

原创示例《潮汐档案馆》是一部港口悬疑群像小说，包含六卷、36 章、32 位有姓名的人物、46 个大纲节点、35 条手动编写的人物关系，以及两条地点和世界观资料。六卷依次为盐纸上的声音、缺席的七个人、闸门以前、九分钟的返潮、下湾的灯、新目录。

正文共 **101,506 个非空白字符**，采用与程序相同的计数方式，包含标点、数字与英文字母，不包含书名、卷名和章节标题。单章 2,800–2,894 字。其中汉字为 90,925 个。这些口径分别列出，避免把纯汉字数与界面字数混用。

`examples/潮汐档案馆.txt` 是可直接阅读的全文；`examples/tide-archive.yejian.json` 包含可编辑的正文、封面、大纲、人物档案、分卷人物记录和章节关联。书架的「载入长篇示例」会创建独立副本，重复载入时自动追加编号。`examples/novel/` 保留逐章源稿及策划资料，`scripts/build-sample.py` 可重建示例文件。

36 章均通过中文创作检查脚本的硬性检查；没有重复的 60 字以上长段落。已对人物名单、七张名卡的身份与去向、第四卷九分钟的连续事件、结尾回收和章节元数据进行一致性检查。示例用于检验写作软件，仍可继续做文学编辑。

## 实际发现并修正的问题

| 检验时的问题 | 本版调整 | 验证结果 |
| --- | --- | --- |
| 六卷 36 章全部展开时，目录过长 | 卷可折叠，自动展开当前卷；标题和正文均可搜索；当前章节滚入目录可视范围 | 从人物和大纲跳到第 36 章，所在卷展开且当前项可见 |
| 从关联跳入正文，输入框聚焦后滚到文末 | 跳转时定位章首，避免聚焦引发滚动 | 真实界面验证光标位置及正文滚动位置均为 0 |
| 46 个大纲节点难以查找 | 搜索标题和内容，保留命中节点的上级路径 | 搜索「新的投递地址」可定位第六卷的第 36 章章纲 |
| 人物、关系与大纲关联的章节选择过长 | 关联选择框可搜索，章节同时显示所属卷 | 可按卷名或章节名称定位，过滤时保留已选关联 |
| 32 人物产生 441 组自动同章提及，图上过密 | 默认显示当前人物与直接关系；手动关系与自动线索分开；自动线索默认关闭；关系索引展开时才生成列表 | 全图为 32 人物、35 手动关系，勾选后另显示 441 组同章提及 |
| 泛称「父亲」作为别名会错误归属人物 | 示例只登记有明确指代的姓名和别名，去掉泛称 | 32 人物均有正文提及；不会把所有「父亲」归到沈峦 |
| 人名候选把「沈砚想」等叙述片段当成人名 | 缩小到姓名加「说／问」等对白线索，过滤已知姓名后缀及常见叙述词 | 完整已登记示例无多余候选；单元测试仍能识别新的双字、三字及复姓候选 |
| 桌面端语言切换等待期间可能继续输入，随后刷新丢失文字 | 保存、持久化语言、等待桌面回调及刷新都在同一次切换锁定中；失败恢复选择框 | 延迟回调、失败及输入法相关回归检查通过 |
| 多次载入示例，重名作品不易区分 | 每次创建新作品及独立卷编号，标题追加 (2)、(3) 等 | 两个副本和其他书互不影响，重命名和排序不破坏章节关联 |
| 桌面服务每次更换端口会影响浏览器草稿缓存 | 桌面草稿与偏好保存在用户目录，脱离临时端口 | 桌面存储与退出保存契约检查通过 |

大纲、人物到正文的跳转以及「返回人物脉络」均在真实浏览器界面操作验证。中文和英文界面都已检查，界面切换后中文书名、卷章标题和正文保持原文。截图为与桌面包相同的本地界面，桌面原生窗口另外完成启动检查。

## 当前边界

- 本版不调用 AI。正文按已登记姓名和别名自动建立提及索引，候选人名需要人工确认；不会自动理解亲属、冲突、人物心理和情节因果。人物关系与分卷变化可以先写，也可以随正文完善。
- 跳转单位是章节，尚无随正文修改而移动的段落锚点。
- Linux x64 已打包和运行验证；Windows/macOS 只有构建配置，尚未生成或验证安装包。Linux 需要 glibc 2.35+、GTK 3 和图形桌面。
- 目前没有账号、云同步、自动更新及多人协作。作品保存在用户数据目录，可导出完整 JSON 备份。
- 私有 GitHub 仓库保存源码、虚构示例与验收文档。用户运行后产生的作品数据库和草稿不上传。
